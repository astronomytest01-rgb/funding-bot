## Назначение

Бот анализирует исторические ставки фандинга, ищет монеты для LONG/SHORT сбора фандинга, показывает историю ставок, считает доход, ищет дельта-нейтральные пары и добавляет Gemini AI как риск-фильтр.

Критично: API бирж, CoinW/Supabase и функция `analyze_rates` взяты из рабочей Claude-версии и являются эталоном. Gemini не меняет расчёт фандинга.


`BINANCE_PROXY_URL` и `BYBIT_PROXY_URL` — HTTP-прокси для обхода геоблокировки Binance (HTTP 451) и Bybit (HTTP 403). Формат: `http://user:pass@host:port`. Если не заданы, запросы идут напрямую. Прокси применяется к вызовам Binance и Bybit для funding history, symbol list и order book quotes (`reports.py`). OI/24h volume через эти прокси не ходят, потому что берутся только из CoinGecko.

`GEMINI_API_KEY` нужен для `/ai`, AI-фильтра `/analyze` и Gemini-рекомендации вечернего отчёта. `REPORT_CHAT_ID` включает вечерний отчёт.

## Фильтры анализа

Основной фильтр `analyze_rates`:

- LONG: стабильные отрицательные ставки или сильный `neg_avg`.
- SHORT: стабильные положительные ставки или сильный `pos_avg`.
- `full`: проходит стабильность по outlier `<= 25%`.
- `partial`: средняя ставка сильная, но стабильность хуже.
- `fail`: не проходит условия.

Дополнительный фильтр актуальности тренда:

- после основного фильтра бот проверяет последние 4 ставки;
- для LONG минимум половина последних ставок должна быть отрицательной;
- для SHORT минимум половина последних ставок должна быть положительной;
- если тренд развернулся к нулю или в другую сторону, монета отбрасывается.

Этот фильтр применяется в `/filter`, `/analyze` и вечернем отчёте.

## Open Interest validation

OI-проверка теперь является частью фильтра. Бот берёт open interest только через CoinGecko Derivatives API по ID биржи, кэширует данные на 10 минут и показывает статус рядом с монетой.

Жёсткий контракт источника: OI/24h volume для этого scanner-бота нельзя брать напрямую из API бирж. Для всех бирж используется CoinGecko Derivatives `derivatives/exchanges/{id}?include_tickers=all`. Native exchange API разрешены только для funding history, symbol list и order book/spread, но не для OI/24h volume.

`oi.py` использует общий кэш CoinGecko tickers на 5 минут: один snapshot биржи питает и OI, и 24h volume. Это снижает риск CoinGecko `429 rate limit`.

Правило отображения:

- монета скрывается из ручного `/analyze`, если подтверждённый OI ниже `$500,000`;
- исключение: для XT hard-порог и зелёный OK-порог OI снижены до `$150,000`, другие биржи остаются на `$500,000` hide / `$1,000,000` OK;
- Aster не фильтруется по OI, значение показывается только информационно;
- автоотчёты `/report`/20:00 и `/longfunding`/22:00 не скрывают монеты по OI; OI показывается только как риск-статус ✅/⚠️/🚫;
- все OI-значения, включая Bitget и Aster, берутся через CoinGecko Derivatives;
- transient CoinGecko errors/429 do not overwrite the last valid OI cache with empty data;
- ⚠️ если OI от `$500,000` до `$1,000,000`, CoinGecko не отдал данные или пары нет в источнике;
- ✅ если OI на конкретной бирже от `$1,000,000`;
- отсутствующие OI-данные не скрывают монету, чтобы не терять рабочие пары из-за неполного источника.

Применяется как hard-filter в ручном `/analyze`. В вечернем отчёте OI показывается отдельно для long-биржи и short-биржи, но не скрывает монеты.

## 24h Volume validation

24h volume/turnover является обязательным ликвидностным фильтром для активных бирж в ручном `/analyze`. Источник 24h volume тоже только CoinGecko Derivatives.

Правило:

- монета скрывается из ручного `/analyze`, если подтверждённый оборот за 24 часа ниже `$400,000`;
- исключение: для XT hard-порог и зелёный OK-порог 24h volume снижены до `$150,000`, другие биржи остаются на `$400,000` hide / `$2,000,000` OK;
- Aster не фильтруется по 24h volume, значение показывается только информационно;
- автоотчёты `/report`/20:00 и `/longfunding`/22:00 не скрывают монеты по 24h volume; Vol24h показывается только как риск-статус ✅/⚠️/🚫;
- ⚠️ если оборот от `$400,000` до `$2,000,000` или данные временно недоступны;
- ✅ если оборот от `$2,000,000`;
- отсутствующие volume-данные не скрывают монету, чтобы не терять рабочие пары из-за rate-limit/API-сбоя, но в Telegram показывается `⚠️ Vol24h: нет данных`.

Источник для всех бирж один: CoinGecko Derivatives по `COINGECKO_DERIVATIVE_IDS` в `oi.py`. Код не должен добавлять native volume-fetchers для отдельных бирж, даже если биржа отдаёт turnover через свой API.

Фильтр применяется как hard-filter в ручном `/analyze`. В вечернем отчёте и при подборе итоговой long/short пары OI/24h volume не скрывают монеты, а выводятся как риск-статус. Команда `/oi` показывает OI и 24h volume вместе.

## Gemini AI

Gemini используется только после фандинг-фильтров:

- `/ai` анализирует фундаментал, инфраструктуру, ликвидность, волатильность, риск движения 30%+ за сутки и риск скама;
- `/analyze` после обычного отчёта отдаёт найденные монеты в Gemini и показывает только те, которые AI оставил для ручной проверки;
- вечерний отчёт показывает Gemini как рекомендацию по FULL-монетам, но не удаляет монеты из отчёта.
- авто-запуск `/longfunding` в 22:00 сначала отправляет полную математическую выдачу без AI-меток. Ниже отдельным блоком показываются только Gemini-рекомендации с причинами; Gemini ничего не удаляет и не переставляет.
- в обоих автоотчётах Gemini запускается только после математических страниц, вне Telegram event loop, и имеет общий жёсткий timeout 90 секунд: если Gemini/API зависает или не отвечает, основной отчёт уже доступен, а бот пишет предупреждение.

## Gemini prompt contract

Gemini не принимает торговое решение и не пересчитывает funding. Его роль — риск-фильтр по активу после того, как монета уже прошла математические фильтры бота.

Bulk prompt для `/analyze` и вечернего отчёта требует:

- отсеять мемкоины, сверхволатильные щиткоины, слабую инфраструктуру и scam-risk;
- оставить только монеты, пригодные для ручной проверки;
- выводить только список оставленных монет;
- формат строки: `[ЭМОДЖИ] [МОНЕТА] — [причина 3-6 слов]`;
- строго использовать 🟢 для LONG и 🔴 для SHORT;
- если подходящих нет, вернуть `Подходящих фундаментальных монет нет`.

В коде есть дополнительная защита: `enforce_direction_emojis()` исправляет emoji в ответе Gemini по направлению из фандинг-фильтра.

Single prompt для `/ai` анализирует только сам актив: фундаментал, инфраструктуру, ликвидность, волатильность, риск движений 30%+ за сутки и scam-risk. Funding-ставки команда `/ai` не анализирует. `/ai` имеет прямой `CommandHandler` до `unknown` и отдельный `user_data["awaiting_ai_coin"]` fallback для пошагового режима, чтобы команда не проваливалась в "Не знаю такой команды" после рестартов/изменений ConversationHandler.

## Команды бота

```text
filter - Анализ монет по фильтрам фандинга
funding - Ставки фандинга по монете
calculator - Калькулятор дохода от фандинга
analyze - Скан рынка + Gemini AI фильтр
ai - Фундаментальный AI-анализ монеты
oi - Пошаговая проверка Open Interest и 24h volume монеты
check - Проверка одной монеты под две ноги и размер позиции
findpair - Дельта-нейтраль: найти пару лонг+шорт
report - Ручной запуск вечернего отчёта
longfunding - Долгосрочные стабильные funding-связки
instruction - Инструкция входа и риск-проверок
settings - Настройки и управление биржами
help - Справка
```

`/filter`:

- пошагово: монеты -> период -> мультивыбор бирж;
- быстрый ввод: `/filter ENJ coinw 7`.

`/funding`:

- история ставок;
- периоды: 1, 3, 7, 14 дней или ручной ввод;
- мультивыбор бирж.
- быстрый ввод: `/funding ENJ phemex 7`;
- зарегистрирован прямым `CommandHandler` до `unknown`; пошаговый режим хранит ожидание монеты/периода в `user_data`, а обработчики вызывают `ApplicationHandlerStop`, чтобы команда не проваливалась в "Не знаю такой команды" после Railway deploy/restart.
- мультивыбор бирж обязан передавать выбранный set в `do_show`; если выбраны две биржи, отчёт идёт только по этим двум, а не по всем.

`/calculator`:

- монета -> сумма -> период -> биржи;
- пресеты суммы: 15000, 20000, 25000.

`/analyze`:

- биржа -> метод -> период;
- long-running scan uses async sleeps and `asyncio.to_thread` for network/OI/volume calls, so Telegram polling is not blocked during large exchange scans;
- методы: `Средняя ставка`, `Средний доход`;
- метод `Средний доход` ищет обе стороны: LONG на устойчиво отрицательном funding и SHORT на устойчиво положительном funding;
- после результата запускается Gemini-фильтр, если есть `GEMINI_API_KEY`;
- в Gemini-результате бот закрепляет emoji по направлению: 🟢 LONG, 🔴 SHORT.

`/ai`:

```text
/ai SOL
/ai SOL ENJ RON
```

`/oi`:

- пошагово: команда -> монета -> мультивыбор бирж кнопками -> подтверждение -> отдельная рекомендация по каждой выбранной бирже;
- использует те же OI-пороги, что ручной `/analyze`: `< $500k` 🚫, `$500k-$1m` ⚠️, `$1m+` ✅;
- показывает 24h volume: `< $400k` 🚫, `$400k-$2m` ⚠️, `$2m+` ✅;
- для XT в `/oi` и ручном `/analyze` hard-пороги и зелёные OK-пороги OI/24h volume равны `$150k`;
- для Aster `/oi` показывает OI/24h volume только как справку; `/analyze` и вечерний отчёт не скрывают Aster по этим значениям;
- зарегистрирована прямым `CommandHandler` до `unknown`, как `/ai` и `/funding`, чтобы не проваливаться в "Не знаю такой команды" после deploy/restart;
- кнопка `Все биржи` работает как toggle: повторное нажатие снимает выделение;
- быстрый ввод: `/oi FLOW`.

`/check`:

- ручная проверка одной монеты под конкретную дельта-нейтральную сделку;
- сценарий: монета -> биржа первой ноги -> направление первой ноги -> биржа второй ноги -> размер позиции в USDT на каждую ногу;
- вторая нога получает противоположное направление автоматически;
- оценивает и печатает долю позиции от OI по каждой бирже для введённого размера, например `$8,000 = 1.14% от OI`; правила: `<2%` ✅, `<10%` ⚠️, `>=10%` 🚫;
- показывает 24h volume как риск-статус, но не меняет настройки `/analyze` и автоотчётов;
- зарегистрирована прямым `CommandHandler` до `unknown`, как `/ai`, `/funding` и `/oi`;
- быстрый ввод: `/check DASH`.

`/findpair`:

```text
/findpair ENJ
/findpair ENJ RON 14
```

`/report`:

- запускает вечерний отчёт вручную в текущий чат;
- использует ту же логику, что авто-отчёт в 20:00 Europe/Kyiv.

`/longfunding`:

- ищет долгосрочные дельта-нейтральные связки со стабильным funding;
- сначала ищет `full` + `partial` сигналы только на биржах, разрешённых как платящая нога; только после этого ищет хедж для найденных монет;
- `kucoin`, `gate`, `mexc`, `binance`, `bybit`, `okx` в longterm-скане не могут быть платящей ногой, но остаются кандидатами на вторую, хеджирующую ногу, если они активны и имеют fetcher в scanner-боте; MEXC в текущем реестре fetcher’ов отсутствует, но заранее внесён в hedge-only политику;
- это ограничение локально для `longterm.py` (7+ дней) и не меняет `/report` в 20:00, краткосрочные сканеры, `/analyze`, `/filter` и `/funding`;
- список хедж-only бирж хранится в одной константе `LONGTERM_HEDGE_ONLY_EXCHANGES`, поэтому любую из бирж можно быстро вернуть в роль платящей;
- группирует результат по монетам: одна монета = одно сообщение = одна лучшая связка (лонг + шорт) по существующему score; альтернативные маршруты остаются внутри расчёта и Gemini, но не выводятся; прежняя переменная `LONGTERM_VARIANTS_PER_COIN` больше не используется;
- для каждой ноги показывает avg funding, выплаты/день, OI, долю `$15k` от OI и Vol24h; ниже показывает чистый funding/день, прибыль на `$8,000` и `$20,000` на ногу и live-спред входа;
- не имеет лимита 180 или 60: загружает полные native-списки всех платящих бирж, анализирует каждую уникальную монету и отдаёт всех прошедших порциями по `LONGTERM_PAGE_SIZE`, по умолчанию 5;
- скан двухэтапный: сначала все монеты платящих бирж проходят `FULL/PARTIAL + recent trend`, затем только для прошедших ищется хедж среди всех бирж;
- BingX, CoinW и OKX имеют собственные native symbol loaders; подстановка списка Phemex запрещена;
- делит выдачу на `📈 Фондовый рынок / TradFi`, `💎 Tier-1` и `🧪 Остальные / щиткоины`; категории и алиасы определяются локально, без Gemini;
- после первой порции каждой категории показывает независимую inline-кнопку `Показать ещё`, которая не запускает повторный скан;
- сохранённая сессия выдачи живёт 2 часа, чтобы хватило времени пролистать полную выдачу;
- кнопка появляется только при наличии следующей страницы математически прошедших монет; Gemini их не уменьшает. Если монет не больше размера страницы, бот явно пишет, что всё показано;
- ранжирует и применяет порог `$300` в месяц по базовой позиции `$20,000` на ногу, но в Telegram дополнительно показывает оценку для `$8,000`;
- ручной `/longfunding` не применяет Gemini и показывает математический результат порциями;
- авто-запуск в 22:00, если задан `GEMINI_API_KEY`, не меняет порядок и вид математических карточек, а ниже отправляет отдельный список Gemini-рекомендаций;
- summary показывает funnel: полный universe, FULL/PARTIAL+trend, наличие хеджа, доходность, funding API requests/empty/errors и Gemini recommendations/reviewed;
- OI, 24h volume и live-спред не скрывают longterm-связки, а служат данными для ручной риск-проверки; если live-котировку получить нельзя, выводится `нет данных`;
- использует текущий список активных бирж из `/settings`.

`/instruction`:

- отправляет инструкцию входа и риск-проверок без запуска отчёта;
- первый пункт инструкции: в ручном `/analyze` OI ниже $500k бот скрывает, $500k-$1m показывает как ⚠️, $1m+ как ✅; 24h volume ниже $400k скрывает, $400k-$2m показывает как ⚠️, $2m+ как ✅; автоотчёты эти значения не скрывают; ордер не должен превышать 1–1.5% от всего OI.

`/settings`:

- inline-кнопки включения/выключения активных бирж;
- состояние не сохраняется после перезапуска.

## Telegram UX и кнопки

Кнопочная логика должна сохраняться как в эталонной Claude-версии. При изменениях нельзя ломать пошаговые сценарии.

- `/filter`: ввод монет -> период `7 дней`, `14 дней`, `Другой период`, `Отмена` -> мультивыбор бирж.
- `/funding`: ввод монеты -> период `1 день`, `3 дня`, `7 дней`, `14 дней`, `Другой период`, `Отмена` -> мультивыбор бирж.
- `/calculator`: ввод монеты -> сумма `15000`, `20000`, `25000`, `Другое`, `Отмена` -> период -> биржи.
- `/analyze`: выбор биржи -> метод `Средняя ставка` или `Средний доход` -> период -> scan progress -> итог -> Gemini-фильтр.
- `/oi`: ввод монеты -> мультивыбор бирж -> подтверждение -> OI + 24h volume рекомендация по каждой выбранной бирже.
- `/check`: ввод монеты -> биржа первой ноги -> направление первой ноги -> биржа второй ноги -> размер позиции -> OI/Vol preview по обеим ногам.
- `/longfunding`: ручной запуск долгосрочного скана -> стартовое сообщение с памяткой о hedge-only биржах -> summary -> отдельные категории TradFi/Tier-1/остальные -> каждый маршрут явно показывает `Платящая` и `Хедж` -> независимые кнопки `Показать ещё`.
- `/settings`: inline-переключатели активных бирж + `Все ВКЛ/ВЫКЛ`.

Тексты Telegram должны оставаться понятными, с emoji и Markdown-форматированием там, где это уже используется.

## Вечерний отчёт

Если задан `REPORT_CHAT_ID`, бот каждый день в 20:00 Europe/Kyiv запускает job queue задачу. Используется timezone `Europe/Kyiv`, поэтому переход на летнее/зимнее время учитывается автоматически.

Отдельный долгосрочный funding-скан запускается каждый день в 22:00 Europe/Kyiv. Для обеих ежедневных задач задано двухчасовое окно допустимого опоздания: краткая задержка scheduler не удаляет запуск. Он использует двухэтапную `/longfunding`-логику без лимита universe. Математическая выдача отправляется первой в `REPORT_CHAT_ID`, а отдельный список Gemini-рекомендаций идёт ниже.

Важно: правило платящей/хеджирующей ноги относится только к этому скану 22:00. Скан 20:00 ниже следует своей прежней логике и не имеет hedge-only списка.

Логика:

1. Сканирует активные биржи.
2. Берёт только `full`-монеты.
3. Применяет фильтр последних 4 ставок.
4. Подбирает лучшую дельта-нейтральную пару по дневной доходности.
5. Нормализует funding по числу выплат в день: 1h/4h/8h биржи сравниваются как дневный funding, а не как одна ставка.
6. Считает live-спред входа по top-of-book: `(SHORT bid / LONG ask * 100) - 100`.
7. Скрывает маршруты с входным spread ниже `AUTO_REPORT_MIN_ENTRY_SPREAD_PCT`, по умолчанию `-0.8%`; если лучший funding-маршрут не проходит, бот пробует следующий маршрут по этой монете.
8. Скрывает маршруты с оценкой ниже `AUTO_REPORT_MIN_DAILY_USD`, по умолчанию `$10/день`; отрицательные маршруты не показываются.
9. Показывает оценку прибыли за 1 день на позицию `AUTO_SCAN_AMOUNT`, по умолчанию `$20,000` на ногу, число выплат/день для long/short бирж и спред входа.
10. Делит математическую выдачу на TradFi, Tier-1 и остальные монеты; у каждой категории своя кнопка `Показать ещё`.
11. Сразу отправляет математические страницы и инструкцию входа, затем отдельным сообщением запускает Gemini-рекомендацию.

## Handler safety contract

Критичные публичные команды не должны зависеть только от `ConversationHandler` entry point, если после них есть общий `unknown` handler. Для команд `/ai`, `/funding`, `/oi` и `/check` используется прямой `CommandHandler` в группе `-1`, текстовый fallback через `user_data` и обязательный `ApplicationHandlerStop` после обработки. Это предотвращает двойной ответ вида "команда сработала" + "Не знаю такой команды".

Правило для будущих правок:

- `unknown` всегда должен быть последним обработчиком команд;
- прямые critical handlers (`/ai`, `/funding`, `/oi`, `/check`, новые аналоги) должны стоять до `unknown` и останавливать propagation;
- если команда использует мультивыбор бирж, выбранный set должен передаваться в бизнес-функцию (`do_analyze`, `do_show`, `do_calc`), а не превращаться в `exchange=None`;
- кнопка `Все биржи` работает как toggle: если все активные биржи уже выбраны, повторное нажатие снимает выделение;
- подтверждение без выбранных бирж не должно запускать скан по всем, бот должен попросить выбрать хотя бы одну биржу.

25. Оба `.md` файла обновлены перед push.

## Ограничения

1. `/settings` хранит состояние только в памяти.
2. CoinW зависит от Supabase collector.
3. Gemini может ошибаться; это только риск-фильтр.
4. Вечерний скан может занимать несколько минут.
5. Telegram режет сообщения длиннее примерно 4096 символов, бот отправляет чанки.
